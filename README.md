#Умный векторный поиск автомобилей с долговременной памятью

CLI-приложение на Python для семантического поиска по базе автомобилей с
запоминанием предпочтений пользователя. Каждая фраза превращается в вектор
смысла (эмбеддинг) специальной языковой моделью и сохраняется в векторной
базе данных Pinecone. При следующем запросе сохранённые факты **автоматически
извлекаются и обогащают исходный запрос**, а затем **жёстко фильтруют** выдачу
по нужным признакам.

---

## Важное замечание об алгоритме

В алгоритме реализовано **умное сохранение фактов** и **обогащение
последующего запроса по базе данных этими фактами**.

Пользователь может в любой момент сохранить факт о своих предпочтениях
(например: «рассматриваю только немецкие машины», «нужен внедорожник»,
«хочу полный привод»). Этот факт не просто лежит в базе — при следующем
поисковом запросе он:

1. **Извлекается** из базы по смысловой близости к текущему запросу.
2. **Обогащает исходный запрос** — текст факта добавляется к запросу, что
   смещает семантику поиска в сторону предпочтений пользователя.
3. **Превращается в жёсткие фильтры** — из факта автоматически извлекаются
   атрибуты (страна, тип кузова, марка, топливо, привод) и применяются
   на стороне базы данных, отсекая неподходящие варианты.

Благодаря этому выдача учитывает не только смысл вопроса, но и **все
ранее сохранённые предпочтения пользователя одновременно**.

## Быстрый старт

### Требования

- Python 3.9+
- API-ключи в файле `.env` (см. [Конфигурация .env](#конфигурация-env))

### Установка

```bash
pip install -r requirements.txt
```

### Базовый сценарий

```bash
# 1. Создать индекс в Pinecone (один раз)
python pinecone_cli.py setup

# 2. Загрузить базу из 25 автомобилей с эмбеддингами и метаданными
python pinecone_cli.py upsert

# 3. Сохранить предпочтение пользователя
python pinecone_cli.py save "Сохрани: пользователь рассматривает только немецкие машины"

# 4. Найти автомобиль — выдача будет отфильтрована по сохранённому факту
python pinecone_cli.py query "какой автомобиль мне купить?"
```

## Как работает каждая команда

Каждый текст (запрос, факт, описание автомобиля) **превращается в эмбеддинг** —
вектор из 1024 чисел, отражающий смысл текста. Это происходит при вызове любой
команды, работающей с базой: `upsert`, `query`, `save`. Эмбеддинг строит
специальная языковая модель (подробности в разделе [Языковая модель](#языковая-модель-эмбеддингов)).

### `setup` — создание индекса

```bash
python pinecone_cli.py setup
```

Создаёт в Pinecone serverless-индекс `vp-autos-facts` с параметрами:
- размерность вектора — 1024 (под модель эмбеддингов);
- метрика — `cosine` (сходство по углу между векторами, т.е. по смыслу).

Если индекс уже существует — выводит его параметры и завершается. Эмбеддинги
на этом шаге не строятся (просто создаётся «контейнер» для векторов).

### `upsert` — загрузка базы автомобилей

```bash
python pinecone_cli.py upsert
```

Загружает 25 описаний автомобилей в индекс. Для каждой записи:

1. Текст описания → эмбеддинг (через языковую модель).
2. В базу сохраняется вектор **и метаданные** — структурированные атрибуты,
   разметка по 5 признакам:
   - `country` — страна происхождения (Германия, Япония, США, …);
   - `body` — тип кузова (седан, внедорожник, спорткар, …);
   - `brand` — марка (BMW, Toyota, Ferrari, …);
   - `fuel` — топливо (бензин, электро);
   - `drive` — привод (полный, …);
   - `type` — `"car"` (служебное поле, отличает авто от фактов).

Метаданные позволяют фильтровать выдачу **точно по атрибутам**, а не только по
смыслу. Между запросами к модели делается пауза 1 секунда (бережём free
rate-limit).

### `query` — семантический поиск с учётом фактов

```bash
python pinecone_cli.py query "какой автомобиль мне купить?"
```

Главная команда. Работает в три этапа:

**Этап 1. Извлечение фактов пользователя.**
Текст запроса → эмбеддинг. По этому эмбеддингу в базе ищутся ранее сохранённые
факты пользователя (записи с `type=fact`), семантически близкие к запросу.

**Этап 2. Обогащение запроса и разбор фильтров.**
Тексты найденных фактов дописываются к исходному запросу, полученный
обогащённый текст → новый эмбеддинг. Параллельно из текстов фактов
извлекаются **жёсткие фильтры**: по словарям алиасов определяются страна,
кузов, марка, топливо и/или привод (если они упомянуты в факте).

**Этап 3. Поиск автомобилей с фильтрацией.**
По обогащённому эмбеддингу ищутся автомобили. Все извлечённые фильтры
собираются в **одно условие AND** и применяются на стороне Pinecone
(server-side filter), то есть неподходящие авто отсекаются ещё до выдачи.
Сами факты из выдачи исключаются. Выводятся top-5 подходящих авто с указанием
всех атрибутов.

Пример: если сохранены факты «только немецкие машины» и «только
внедорожник», команда `query "какой автомобиль мне купить?"` выдаст только
немецкие внедорожники.

### `save` — сохранение факта пользователя

```bash
python pinecone_cli.py save "Сохрани: пользователь хочет только внедорожник"
```

Сохраняет факт в базу, если сообщение начинается с триггера
(`сохрани` / `запомни` / `save` / `remember`). Триггер отрезается, оставшийся
текст:

1. → эмбеддинг (через языковую модель);
2. сохраняется в индекс с метаданными `{text, type="fact"}`.

Факт не размечается по атрибутам при сохранении — разбор на фильтры
происходит позже, в момент `query`. Это позволяет сохранять **произвольные**
факты на естественном языке.

### `stats` — статистика индекса

```bash
python pinecone_cli.py stats
```

Выводит общее число векторов в индексе и распределение по namespace. Эмбеддинги
не строятся — это служебная команда для контроля состояния базы.

### `test-embed` — проверка эмбеддинга

```bash
python pinecone_cli.py test-embed "быстрая машина"
```

Возвращает размерность вектора (1024) и первые 5 чисел — для проверки, что
языковая модель доступна и работает. Удобно для отладки соединения.

## Языковая модель эмбеддингов

Для построения векторов смысла задействована **специальная языковая модель**
эмбеддингов — `liquid/lfm-2.5-embedding-350m:free`, доступная через OpenRouter.
Это не чат-модель (она не генерирует текст), а модель-кодировщик: её задача —
перевести любой текст в числовой вектор так, чтобы у смыслу-близких текстов
получались близкие векторы.

### Что делает модель

- **На входе** — текст (запрос пользователя, описание авто, факт).
- **На выходе** — вектор из 1024 чисел (координаты смысла).
- Тексты с одинаковым смыслом («быстрая машина» и «спортивный автомобиль»)
  получают почти совпадающие векторы, даже если слова разные.
- Модель многоязычная — запрос на русском находит семантически близкие
  описания независимо от точного совпадения слов.

### Почему векторы, а не поиск по словам

Обычный поиск требует совпадения слов: запрос «быстрая машина» не найдёт
текст «спортивный автомобиль с высокой скоростью». Векторный поиск сравнивает
**смысл**: косинусное расстояние между эмбеддингами показывает, насколько
тексты близки по содержанию, и работает с синонимами, перефразированием и
разной формулировкой.

### Защита от перехвата TLS

На Windows при корпоративном прокси или антивирусе с перехватом TLS Python
может не доверять сертификату перехвата. Для решения используется модуль
`truststore` — он заставляет Python доверять системному Windows-хранилищу
сертификатов. Уже подключён в начале `pinecone_cli.py`, работает автоматически.

## Конфигурация .env

Файл `.env` в корне проекта (не попадает в git — см. `.gitignore`):

```env
OR_KEY=sk-or-v1-...                              # API-ключ OpenRouter
OR_Model=liquid/lfm-2.5-embedding-350m:free      # модель эмбеддингов (1024 dim)
Pinecone_API=pcsk_...                            # API-ключ Pinecone
```
